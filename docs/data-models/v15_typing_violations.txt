--- CRITICAL (data loss — leading zeros destroyed) ---

NONE. No identifier columns with leading zeros are typed as numeric.
All NDC, NPI, GPI, DEA, MBI, taxonomy, AHFS columns are correctly STRING.

--- HIGH (type mismatch or interop risk) ---

1. claim.rx_claim.ncpdp_id
   Current: BIGINT  ->  Required: STRING
   FK target: drug.pharmacy.ncpdp_id (VARCHAR)
   Reason: Type mismatch. FK column is BIGINT but target is VARCHAR.
   The value_regex on dur_event's ncpdp_id shows ^[0-9]{7}$ confirming
   this holds a 7-digit NCPDP number, not a surrogate. BIGINT drops
   leading zeros in NCPDP IDs like 0123456.

2. client.audit_finding.ncpdp_id
   Current: BIGINT  ->  Required: STRING
   FK target: drug.pharmacy.ncpdp_id (VARCHAR)
   Reason: Same type mismatch as #1. Description says "7-digit NCPDP
   identifier" and value_regex is ^[0-9]{7}$.

3. claim.dur_event.ncpdp_id
   Current: BIGINT  ->  Required: STRING
   FK target: drug.pharmacy.ncpdp_id (VARCHAR)
   Reason: Same type mismatch as #1. Description explicitly says
   "7-digit NCPDP identifier" and value_regex is ^[0-9]{7}$.

--- MEDIUM (naming convention, not data loss) ---

4. drug.classification.ndc_id
   Current: VARCHAR, FK-> drug.ndc.ndc_code
   Issue: Column named "ndc_id" but holds a VARCHAR NDC string (FK to
   ndc_code natural key), not a BIGINT surrogate. The _id suffix implies
   surrogate. Should be renamed to ndc_code for consistency.

5. drug.formulary_drug.ndc_id
   Current: VARCHAR, FK-> drug.ndc.ndc_code
   Issue: Same as #4. Named "ndc_id" but holds NDC string value.
   Should be ndc_code.

6. claim.prior_auth.formulary_tier
   Current: INT
   Issue: Formulary tiers can have non-numeric variants (specialty,
   excluded, not_listed). STRING would be more robust. INT is functional
   but fragile if tier classification evolves.

--- STRUCTURAL GAPS (not typing violations, but significant) ---

G1. claim.rx_claim has NO foreign key to drug.ndc.
    The rx_claim table has an "ndc" STRING column (the 11-digit code) but
    no surrogate FK (ndc_id BIGINT) to drug.ndc.ndc_id. This was Priority 1
    in next_vibes_v9 and has failed to land across v6-v15. Claims cannot
    join to the drug reference dimension without a string match.

G2. claim.rebate_record has NO NDC column.
    Has gpi_code (STRING) for class-level identification but no NDC field.
    Claim-level rebate records tied to a specific dispensed product cannot
    be traced to a drug. The table description mentions "drug NDC or GPI"
    but only GPI exists.

G3. program domain does not exist.
    The vibes_program.txt directives (15 tables across savings programs,
    rebates, accumulators, 340B, etc.) did not produce a program domain
    in v15. The v10 error log showed the agent accepted them as
    "new_containers" but hit structural failures during application.

SUMMARY
=========================================================================

  v10 fixes applied:    6 of 9 applicable (67%)
  CRITICAL violations:  0
  HIGH violations:      3  (all NCPDP BIGINT — same class, same fix)
  MEDIUM violations:    3  (2 naming, 1 tier type)
  Structural gaps:      3  (no rx_claim->drug.ndc FK, no NDC on rebate_record,
                            no program domain)

The v15 model is substantially cleaner than v10. The only remaining typing
bugs are 3 ncpdp_id columns (rx_claim, dur_event, audit_finding) still
typed BIGINT instead of STRING — identical to the v10 findings that were
not fixed. Everything else passes: NDC, NPI, GPI, DEA, MBI, taxonomy,
DAW, gender, claim_status, ZIP, phone, financials, surrogates, booleans.

The structural gaps (no claim->drug FK, missing NDC on rebate_record,
missing program domain) are more impactful than the typing issues at
this point.
